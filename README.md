# audio_speed_calc

**Расчёт скорости автомобиля по звуку двигателя из .ts-фрагментов (видеорегистратор).**

Утилита выделяет спектрограмму аудиодорожки, находит гармоники частоты вращения коленвала (H5 и H4), по ним вычисляет скорость, сопоставляет с GPS и позволяет визуально контролировать результат на графике.

Текущая версия по коду: **v0.57.8** (с поведенческими патчами v0.57.9–v0.57.9.2, см. «История изменений»).

## 1. Что делает программа

1. Извлекает аудио из `.ts` через `ffmpeg`.
2. Считает STFT (спектрограмму) с окном 32768 сэмплов и шагом `1 / target_fps`.
3. Пользователь кликами мыши выбирает 5-ю и 4-ю гармоники частоты вращения.
4. По выбранным гармоникам считается частота `f0`, обороты `n` и скорость `V`:

   ```
   f0 = (H5/5 + H4/4) / 2
   n  = 60 * f0 * stroke / cylinders
   V  = 0.377 * Rk * n / (Io * Ik)
   ```

   где `Rk = c_def * P * H / 100000 + 0.0127 * R` — динамический радиус шины.

5. Для каждого шага анализа находит границы (min/max) гармоник выбранным алгоритмом (6 вариантов).
6. Извлекает GPS-точки из `.ts` (exiftool → бинарный разбор PID `0x0300`), валидирует, добирает из соседних файлов, считает dGPS-сдвиг.
7. Рисует интерактивный график с наложением кривых GPS-H5 / GPS-H4 и реальных треков аудио, подписями пиков и маркерами Vmax/Vmin.
8. Сохраняет отчёт `_speed_report_algoN.txt`, PNG-скриншот и диагностический лог GPS-лага.

## 4. Интерфейс

### 4.1 График

- **Спектрограмма** (палитра `inferno`) либо контурный Power Spectrum.
- **Линии гармоник** `H1..Hn` с подписями.
- **Жёлтая линия** — реальный трек H4 (min/max/центр).
- **Голубая линия** — реальный трек H5.
- **Маджента `#ff00cc`** — кривая GPS→H5 (при включённой кнопке «GPS→H5»).
- **Голубая `#00ccff`** — кривая GPS→H4 (при включённой кнопке «GPS→H4»).
- **Подписи пиков** — только при включённой «Подп.V»; см. п. 4.3.
- **Vmax / Vmin** — автоматически показываются, когда «Подп.V» **отжата**.

### 4.2 Столбец кнопок (правый)

Верхние три — GPS-оверлей:

| Кнопка | Что включает | Цвет активной кнопки |
|---|---|---|
| **GPS→H5** | кривая GPS-H5 (маджента) | светло-маджента `#ff99ff` |
| **GPS→H4** | кривая GPS-H4 (голубая) | светло-голубая `#99eeff` |
| **Подп.V** | подписи пиков всех активных источников | светло-жёлтая `#ffffcc` |

**«Все 3»** — один клик зажигает (или гасит) все три кнопки разом.

Основное меню:

- **Спектр** — переключение time / power.
- **5я гармоника**, **4я гармоника** — выбор гармоник кликом.
- **1.dB … 6.RMS** — 6 алгоритмов выделения границ; рядом с каждой кнопкой `?` — справка.
- **Прям. / Факт. / Оба / Выкл** — режим оверлея min/max.
- **Сб.время / Сб.част / Сброс** — сброс осей.
- **Назад / Вперед / Удалить поз. / Применить / Выход** — история и завершение.

### 4.3 Подписи пиков

Цвета подписей:

| Источник | Цвет |
|---|---|
| GPS-H5 | маджента `#ff00cc` |
| GPS-H4 | голубая `#00ccff` |
| Реальный трек H5 | жёлтый `#ffff00` |
| Реальный трек H4 | зелёный `#00ff00` |

**Фильтр налезающих подписей.** Работает по обоим методам:

- `_draw_speed_labels` — когда **«Подп.V» включена**;
- `_draw_speed_extremes` — когда **«Подп.V» выключена** (маркеры Vmax/Vmin).

Логика одинаковая: все кандидаты собираются в буфер, сортируются по X, и если новая подпись попадает в прямоугольник `min_dx × min_dy` от уже принятой, она отбрасывается. Пороги — доли видимого диапазона осей:

```json
"label_pad_x_frac": 0.10,
"label_pad_y_frac": 0.06
```

**Как подстраивать:**

| Хотите | Что менять |
|---|---|
| Реже подписи | увеличить `label_pad_x_frac` до `0.12–0.15` |
| Чаще подписи | уменьшить до `0.06–0.08` |
| Не налезают по вертикали (маджента на голубой) | увеличить `label_pad_y_frac` до `0.08` |

В консоль при каждой отрисовке печатается диагностика:

```
[labels]   candidates=47 kept=22 min_dx=140.0frames min_dy=4.0Hz
[extremes] candidates=6  kept=4  min_dx=178.0frames min_dy=6.0Hz
```

### 4.4 Поля ввода (внизу)

| Поле | Смысл | Диапазон |
|---|---|---|
| `Xнач,с` | начало окна по времени | ≥ 0 |
| `Xкон,с` | конец окна | ≤ длительность |
| `dX,с` | ширина окна | > 0 |
| `Fmin`, `Fmax` | диапазон частот | 20–600 по умолчанию |
| `Шир` | полуширина полос гармоник | 1–20 |
| `Шаг` | шаг расчёта | 0.01–5.0 с |
| `Цвет` | порог алгоритма | 1–255 |
| `Пик` | полуширина поиска пика | 1–30 Гц |

Навигация по полям — `Tab` / `Shift+Tab`.

### 4.5 Горячие клавиши

| Клавиша | Действие |
|---|---|
| `?` или `Shift+/` | справка |
| `Q` | выход |
| `S` | сохранить конфиг + PNG + отчёт |

### 5.3 Параметры автомобиля

```json
{
  "algorithm": 2,
  "cylinders": 4,
  "stroke": 2,
  "tire_width": 235,
  "tire_profile": 70,
  "rim_diameter": 16,

`tire_deflection_coeff` (v0.57.8) — коэффициент смятия профиля шины под нагрузкой. Дефолт `0.84` для радиальной легковой 235/70 R16. Классическое значение `0.85`.   "gps_trim_fft_edges": true,

}
```

- `gps_smooth_sec` — окно сглаживания обоих сигналов перед корреляцией.
- `gps_lag_from_history` — считать dGPS по самому длинному интервалу из истории; `false` — по текущему окну.

## 6. Алгоритмы выделения границ (1..6)

| № | Название | Порог |
|---|---|---|
| 1 | Абсолютный dB | `vmin + (цвет/255)*(vmax-vmin)` |
| 2 | Индекс палитры | `idx_центра - цвет` |
| 3 | Относительный от пика | `dB_пика - цвет` |
| 4 | Адаптивный от шума | `медиана_шума + цвет * сигма` |
| 5 | Половинная мощность | `dB_пика - (цвет/255)*3` |
| 6 | RMS-интегрирование | доля `цвет/255` от суммарной мощности |

Подробности — по кнопке `?` рядом с каждым алгоритмом.

## 7. Формулы и логика

```
f5 = H5ц / 5
f4 = H4ц / 4
f  = (f5 + f4) / 2
n  = 60 * f * stroke / cylinders
Rk = c_def * P * H / 100000 + 0.0127 * R
V  = 0.377 * Rk * n / (Io * Ik)

df = ((H5max-H5min)/5 + (H4max-H4min)/4) / 2 / 2
dn = 60 * df * stroke / cyl
dV = 0.377 * Rk * dn / (Io * Ik)
```

Обозначения:

- `P`, `H` — ширина и профиль шины (мм);
- `R` — посадочный диаметр диска (дюймы);
- `Io` — передаточное главной пары;
- `Ik` — передаточное текущей передачи КПП;
- `stroke` — 1 для 2-тактного, 2 для 4-тактного;
- `cylinders` — число цилиндров.

## 8. GPS-обработка

### 8.1 Извлечение

1. `exiftool -ee3 -n` — быстрый путь, если установлен.
2. Прямой бинарный разбор `.ts` (PID `0x0300`, PES-заголовок `00 00 01 BF`).
3. `gps_to_relative_time` — перевод абсолютного времени в относительное от первой метки.

### 8.2 Калибровка dGPS

`find_gps_lag` ищет **минимум RMSE(|Vg − Va|)** по всем сдвигам в `±5 с` шагом `0.1 с`. При равенстве RMSE (в пределах `1e-6`) — tie-breaker по максимуму корреляции Пирсона. Дополнительно — субшаговая локализация параболой через три точки вокруг минимума.

**history-калибровка** (`gps_lag_from_history = true`): если в истории есть окно длиннее текущего, dGPS считается на самом длинном интервале, кэшируется и применяется ко всем коротким. Кэш сбрасывается при смене H5/H4. В статусной строке применение помечается меткой `(H)`.

### 8.3 Диагностический лог

Файл `<base_ts>_gps_lag_diag.log` и CSV `<base_ts>_gps_lag_diag.csv`:

- Секция 0 — легенда и конвенции.
- Секция 1 — все GPS-точки.
- Секция 2 — все аудио-точки.
- Секция 3 — статистика сигналов.
- Секция 4 — перекрытие при `lag=0`.
- Секция 5 — все сдвиги в `±5 с` шагом `0.1 с`.
- Секция 6 — все сдвиги в `±60 с`.
- Секция 7 — сверхширокий `±300 с`.
- Секция 8 — контрольные сдвиги.
- Секция 9 — парные данные на лучшем сдвиге.
- Секция 10 — вердикт.
- Секция 11 — зоны недоверия.

## 10. Отчёты и статусная строка

### 10.1 Отчёт `_speed_report_algoN.txt`

Содержит:

- диапазон анализа (кадры, время, шаг, число шагов);
- сведения о компьютере, диске, скрипте (из `sys_fingerprint`);
- параметры автомобиля и формулы;
- пошаговую таблицу с подстановками для каждого шага;
- итог Vmin / Vmax / Vср с погрешностями;
- GPS-сравнение (метод, число меток, запаздывание, соседние точки, Vgps ср, dV);
- список PNG-скриншотов (если сохранены).

### 10.2 Статусная строка внизу окна

Пример:

```
[5/5] | Ист: 3/7 * | Шаг=0.100с | Диап: кадры 300-1800 (10.000-60.000с) |
Готово | Алго 2: Индекс палитры | H5=505.0 Гц | H4=445.0 Гц | f0=100.5 Гц |
Vср=105.3 км/ч | Vgps ср=104.8 км/ч | Δgps=+1.500с (H)
```

- `*` рядом с `Ист:` — есть неприменённые правки.
- `(H)` — dGPS применён из history-калибровки.
- `(OVR)` — dGPS задан `gps_lag_override` из JSON.

## 13. Известные ограничения

- Если `std(V_audio)` и `std(V_GPS)` меньше 1 км/ч, корреляция вырождается — вердикт диагностики в этом случае предупреждает «нет динамики».
- При уровне РЭБ/помех GPS-точек может не хватить — программа доберёт из соседних `.ts` (см. п. 5.5), либо придётся задать `gps_lag_override` вручную.
- В очень узких окнах анализа (<3 GPS-точки) скорость интерполируется на границах и в центре (`_gps_view_samples`).
- Извлечение GPS через `exiftool` для больших `.ts` может занять до 2 минут на файл.
- Подписи пиков и маркеры Vmax/Vmin рисуются с фильтром X+Y; пороги настраиваются через `label_pad_x_frac` / `label_pad_y_frac`. Если увеличить их слишком сильно, часть нужных пиков не будет подписана — это ожидаемое поведение.
