## Введение

Программа **audio_speed_calc** реализует методику определения скорости транспортного средства (ТС) по звукозаписям автомобильного видеорегистратора. Метод разработан в ФБУ Челябинская ЛСЭ Минюста России **А.А. Годлевским** и прошёл апробацию ведущими государственными судебными экспертами ФБУ Сибирский РЦСЭ и ФБУ Томская ЛСЭ Минюста России.

Руководство объединяет:

- изложение теоретических основ метода;
- описание работы с программой `audio_speed_calc`;
- описание настройки через JSON-конфиг с указанием ситуаций, в которых требуется ручная правка параметров;
- список ссылочных материалов (нормативных, научных, инструментальных);
- пример расчёта из экспертной практики.

## 1. Назначение и область применения

### 1.1. Назначение

Программа предназначена для определения скорости движения ТС путём инструментального анализа звукового ряда видеофонограмм, полученных с автомобильных видеорегистраторов. Метод основан на выделении гармонических составляющих шума работающего ДВС и последующем пересчёте частоты рабочего цикла двигателя в скорость движения ТС с учётом передаточных чисел трансмиссии и геометрических параметров шин.

**Программа позволяет:**

- определять частоту вращения коленчатого вала (об/мин) по звукозаписи;
- рассчитывать скорость движения ТС в любой момент видеофонограммы;
- строить графики зависимости скорости от времени;
- сопоставлять результаты с GPS-данными из видеофайла (при наличии);
- формировать отчёты для судебно-экспертной практики.

### 1.2. Область применения

- **Судебная экспертиза ДТП** — определение скорости ТС перед происшествием, особенно в условиях ограниченной видимости или отсутствия ориентиров на местности.
- **Автотехническая экспертиза** — проверка показаний участников ДТП.
- **Научно-исследовательские задачи** — анализ акустических характеристик работы ДВС.

### 1.3. Ограничения

- Метод применим для ТС с **механической коробкой передач (МКПП)**. Для АКПП требуется дополнительное определение номера включённой передачи.
- Точность зависит от качества звукозаписи и шумовой обстановки в салоне.
- Требуется знание передаточных чисел КПП и главной передачи, а также маркировки шин.
- Подписи пиков на графике рисуются с фильтром, предотвращающим наложение. Пороги фильтра настраиваются (`label_pad_x_frac`, `label_pad_y_frac`).

## 2. Теоретические основы метода

### 2.1. Физическая сущность

Микрофон видеорегистратора фиксирует акустические колебания, возникающие при работе ДВС. Наиболее выраженной гармонической составляющей является шум выпуска — периодический сигнал, частота которого равна частоте рабочего цикла двигателя.

Для четырёхтактного двигателя полный рабочий цикл совершается за два оборота коленчатого вала. Для двухтактного — за один оборот.

Чувствительность микрофонов большинства видеорегистраторов позволяет фиксировать звуки на частотах от 20 Гц и выше. Низкочастотные сигналы поступают на микрофон за счёт вибрации кузова.

### 2.2. Основные формулы

**Частота вращения двигателя (об/мин):**

```
n = 60 · f · (2 / k) = 120 · f / k       (1)
```

где `n` — частота вращения коленчатого вала, об/мин;
`f` — частота рабочего цикла (гармоники), Гц;
`k` — количество цилиндров;
`2` — количество оборотов коленвала за один рабочий цикл.

**Средняя скорость ТС (км/ч):**

```
V = 3,6 · Sk / T                          (2)
```

где `Sk` — путь, пройденный колесом за один оборот, м;
`T` — период вращения колеса, с.

**Путь за один оборот:**

```
Sk = 2 · π · rk                           (3)
```

**Период вращения колеса:**

```
T = 60 · i0 · ik / n                      (4)
```

где `i0` — передаточное число главной передачи;
`ik` — передаточное число включённой передачи КПП.

**Итоговая скорость (км/ч):**

```
V = 0,377 · rk · n / (i0 · ik)            (5)
```

**Радиус качения колеса (м):**

```
rk = 10⁻⁵ · λ · P · H + 0,0127 · R        (6)
```

где `λ` — коэффициент смятия шины (0,85–0,90 для диагональных; 0,80–0,85 для радиальных);
`P` — ширина протектора, мм;
`H` — профиль шины, %;
`R` — посадочный диаметр, дюймы.

> **Примечание к v0.57.8.** Коэффициент смятия шины вынесен в конфиг как `tire_deflection_coeff`. Дефолт `0.84` — для радиальной легковой 235/70 R16. При переходе 0.85 → 0.84 все скорости уменьшаются на 0.466 %.

### 2.3. Соответствие между H5, H4 и фундаментальной частотой

```
H5 = 5 · f₀
H4 = 4 · f₀
f₀ = (H5/5 + H4/4) / 2
```

| Обороты, об/мин | f₀, Гц | H4, Гц | H5, Гц |
|---|---|---|---|
| 800 (холостые) | ≈ 27 | ≈ 108 | ≈ 135 |
| 1500 | ≈ 50 | ≈ 200 | ≈ 250 |
| 3000 | ≈ 100 | ≈ 400 | ≈ 500 |
| 4500 | ≈ 150 | ≈ 600 | ≈ 750 |
| 6000 | ≈ 200 | ≈ 800 | ≈ 1000 |

### 2.4. Определение номера передачи

```
nK+1 / nK = iK+1 / iK                     (7)
```

Например, при переключении с I на II передачу частота гармоники меняется в 1,74–1,75 раза, что соответствует отношению передаточных чисел.

## 5. Быстрый старт

Базовая команда запуска:

```bash
python audio_speed_calc.py path/to/file.TS
```

С сохранением всего текстового вывода в файл:

```bash
python audio_speed_calc.py path/to/file.TS 1>rez.txt
```

**При первом запуске:**

1. Программа извлечёт аудио и построит спектрограмму.
2. Откроется консольный запрос параметров автомобиля.
3. Нажмите **Enter** (согласиться) или **n** (ввести новые).
4. В окне программы кликните мышью сначала по **5-й гармонике**, затем по **4-й гармонике**. Ориентиры для 4-тактного 4-цилиндрового двигателя:
   - холостые (~800 об/мин): f₀ ≈ 27 Гц, **H5 ≈ 135 Гц**, **H4 ≈ 108 Гц**;
   - 3000 об/мин: f₀ ≈ 100 Гц, **H5 ≈ 500 Гц**, **H4 ≈ 400 Гц**;
   - 6000 об/мин: f₀ ≈ 200 Гц, **H5 ≈ 1000 Гц**, **H4 ≈ 800 Гц**.
   
   Здесь f₀ — фундаментальная частота, H5 = 5·f₀, H4 = 4·f₀. На графике подписи `H1=…`, `H5=…`, `H4=…` рисуются горизонтальными линиями.
5. Нажмите кнопку алгоритма (`1.dB` … `6.RMS`) или клавишу **1**–**6**.
6. Изучите результаты в консоли и на графике.
7. Нажмите **A** («Применить»), чтобы зафиксировать результат.

> **Частая ошибка.** Клик по «50–100 Гц» — это **фундаментальная** частота f₀, а не гармоника. Для H5 и H4 нужно кликать **выше**: при f₀ = 100 Гц: H5 = 500 Гц, H4 = 400 Гц.

## 7. Логика расчёта и формулы

### 7.1. Последовательность расчёта

1. Извлечение аудио из .ts-файла через `ffmpeg`.
2. Построение спектрограммы (БПФ, окно Ханна, fft_size 32768).
3. Выбор гармоник H5 и H4 кликом мыши.
4. Отслеживание гармоник по кадрам (rolling-трекинг пика).
5. Расчёт частоты f = (f5/5 + f4/4) / 2.
6. Расчёт оборотов n = 60 · f · stroke / cylinders.
7. Расчёт скорости V = 0,377 · rk · n / (i0 · ik).
8. Расчёт rk по формуле (6) с коэффициентом `tire_deflection_coeff`.

### 7.2. Алгоритмы выделения границ

| Алгоритм | Метод |
|---|---|
| 1.dB | Абсолютный порог в dB |
| 2.Пал | Индекс палитры |
| 3.Отн | Относительный от пика |
| 4.Шум | Адаптивный от шума |
| 5.-3dB | Половинная мощность |
| 6.RMS | RMS-интегрирование |

### 7.3. Калибровка GPS

1. Извлечение GPS-меток (exiftool или встроенный парсер PID 0x0300).
2. Валидация точек: отбрасывает (0,0), эпоха вне окна, V > 300 км/ч.
3. Добор из соседних .ts при нехватке точек.
4. Определение зон недоверия (скачки ускорения).
5. Поиск dGPS — минимум RMSE(|Vg − Va|) по сдвигам ±5 с шагом 0.1 с.
6. History-калибровка по самому длинному интервалу. В статусе — (H).

## 8. Настройка через JSON-конфиг

Все настройки программы хранятся в JSON-файле. Часть параметров удобно менять прямо в окне (поля ввода, кнопки). Другая часть доступна только через правку JSON в текстовом редакторе. Этот раздел описывает, **какие параметры имеет смысл править вручную и при каких ситуациях**.

### 8.1. Расположение и порядок применения

Файл конфига лежит рядом с `.ts`-файлом и называется `<base_ts>_config.json`. Например, для `20260602050735_000048.TS` — файл `20260602050735_000048_config.json`.

При запуске параметры собираются в три слоя:

1. **DEFAULT_CONFIG** — дефолты внутри кода;
2. **audio_speed_config.json** — общий шаблон в рабочей папке (если существует);
3. **`<base_ts>_config.json`** — файл этого конкретного видеофайла.

Более поздний слой перезаписывает более ранний. Если в файле параметра нет — берётся значение из предыдущего слоя.

> **Как записать конфиг на диск.** Только клавиша `S` в окне программы. Кнопка «Выход», закрытие окна крестиком и сохранение PNG конфиг на диск **не пишут**. Правки в JSON из блокнота нужно **сохранять и перезапускать программу**.

### 8.11. Типовые ситуации «симптом → параметр»

**Скорости по аудио стабильно завышены или занижены относительно GPS.**
Правьте `tire_deflection_coeff` по формуле `c_new = c_old · (1 − k/100)`, где k — расхождение в %. Пример: V_аудио на 1 % выше GPS → `c = 0.84 · 0.99 = 0.832`.

**Программа не находит нужные гармоники на спектрограмме.**
Проверьте `freq_min` / `freq_max` — гармоника может быть за пределами окна. Затем `peak_search_hz` — увеличьте до 10–15, если гармоника сильно дрейфует.

**Подписи скоростей налезают друг на друга.**
Увеличьте `label_pad_x_frac` до 0.12–0.15 (горизонталь) или `label_pad_y_frac` до 0.08 (вертикаль, для пересечения мадженты и голубой GPS-кривой).

**dGPS явно неверный (например, ±7 с).**
Задайте `gps_lag_override` вручную — впишите ожидаемое значение (например, `1.5` или `-2.0`).

**GPS-точек мало (РЭБ, помехи).**
Проверьте `neighbor_gps_enabled` (должен быть `true`). Увеличьте `neighbor_extend_sec` до 60–120. Уменьшите `doubt_min_points` до 8.

**Корреляция скачет из-за одиночных «выбросов» GPS.**
Убедитесь, что `doubt_zones_enabled = true`. Уменьшите `doubt_radius_sec` до 0.5–1.0.

**Программа считает долго на длинных файлах.**
Увеличьте `time_step` до 0.2–0.5. Уменьшите `fft_size` до 16384. Уменьшите `report_duration`.

**dGPS из истории портит короткие окна.**
Установите `gps_lag_from_history = false`. Каждое окно будет считать dGPS по себе.

**Расчёт пошёл по «не той» гармонике (f/2 или 2f).**
Сузьте `peak_search_hz` до 2–3. Проверьте по графику, что клик попал на линию H5 (5·f₀).

**Передаточное число КПП неизвестно.**
Используйте формулу (7) — отношение частот при переключении даст передаточное число. Затем впишите в `gear_ratio`.

### 8.12. Чего делать не нужно

- `sample_rate`, `fft_size`, `target_fps` — связаны друг с другом и с физикой аудио.
- `view_history` — управляется программой.
- `view_x_start`, `view_x_end` и т. п. — сохраняются кнопкой S автоматически.
- `algorithm` — управляется кнопками 1–6.
- `harmonic_5_freq`, `harmonic_4_freq` — сохраняются при клике мышью.

### 8.13. Откат и бэкап

1. Перед правкой конфига сделайте копию: `copy <base>_config.json <base>_config.json.bak`.
2. Если после правки программа ведёт себя неадекватно — верните файл из бэкапа.
3. Если бэкапа нет — удалите файл конфига. Программа создаст новый из дефолтов.

## Приложение А. Пример расчёта

### А.1. Исходные данные

| Параметр | Значение |
|---|---|
| ТС | легковой автомобиль, 4 цилиндра, 4-тактный |
| Шины | 235/70 R16 |
| Цилиндров | 4 |
| Передаточные числа | i0 = 4,875; ik = 0,802 |
| H5 | 504,6 Гц |
| H4 | 446,7 Гц |

### А.2. Расчёт

**1. Частота рабочего цикла:**

```
f5 = 504,6 / 5 = 100,92 Гц
f4 = 446,7 / 4 = 111,68 Гц
f  = (100,92 + 111,68) / 2 = 106,3 Гц
```

**2. Обороты:**

```
n = 120 · 106,3 / 4 = 3189 об/мин
```

**3. Радиус качения:**

```
rk = 10⁻⁵ · 0,84 · 235 · 70 + 0,0127 · 16 = 0,339 м
```

**4. Скорость:**

```
V = 0,377 · 0,339 · 3189 / (4,875 · 0,802) ≈ 104,3 км/ч
```

### А.3. Результат

- При c_def = 0,84 — **104,3 км/ч**.
- При c_def = 0,85 — **105,5 км/ч**.
- Средняя по программе: **Vср = 105,3 км/ч**; по GPS: **Vgps ср = 105,4 км/ч**. Расхождение < 1 %.

### А.4. Определение номера передачи

| Передача | Частота, Гц | Отношение к пред. | Отношение i |
|---|---|---|---|
| I | 92 | — | — |
| II | 53 | 92/53 ≈ 1,74 | 1,75 |
| III | 56 | 87/56 ≈ 1,58 | 1,54 |
| IV | 68 | 92/68 ≈ 1,35 | 1,36 |

### А.5. Верификация из практики

ДТП с участием тягача и ВАЗ-21099 с видеорегистратором позади. f = 75,5 Гц → n = 2265 об/мин. Параметры: rk = 0,28 м; i0 = 3,94; iv = 0,784.

```
V = 0,377 · 2265 · 0,28 / (3,94 · 0,784) ≈ 77,4 км/ч
```

По следам торможения — 78 км/ч. Совпадение подтверждает работоспособность метода.
